# Bazarbot: базарики, тарифы, расширенное аудио и выпуск на vserv

Статус: согласованные требования и план, **НЕ реализовано** в main.
Дата: 2026-10-28.
Основная задача: #17. Этапы: #18–#24.
Источник фактического кода: актуальный main; источник фактического runtime: отдельная проверка vserv.
Существующая эксплуатационная процедура: docs/update_procedure_ru.md.

## 1. Цель и границы

Добавить точный денежный учёт распознавания через RouterAI, индивидуальные и групповые расчётные периоды, разовое пополнение, расширенное ручное распознавание файлов, пользовательскую и администраторскую справку. Не изменять автоматически обработку обычных аудиофайлов; автоматически принимается только Telegram voice. Запуск новой функциональности на vserv только по отдельному поручению владельца.

В первой версии не реализуются: автоматический приём реальных платежей, тяжёлое локальное ASR, получение истории Telegram через пользовательский аккаунт, видео и длинные записи по частям, отдельная тарификация Telegram topics, Max (#8/#9 отложены), автоматическая установка новых версий кода.

## 2. Единицы и точность

- 1 базарик (Б) = 0,01 ₽. Личное бесплатное начисление 1000 Б за месяц. Отдельный групповой месячный бюджет, предлагаемый начальный размер 10 000 Б.
- Базарики дробные. Применять decimal.Decimal для входящих цен и вычислений, исключить float и SQLite REAL из нового финансового учёта. Парсить JSON провайдера с parse_float=Decimal, цену сохранять как исходную десятичную строку вместе с валютой RUB.
- Долговечные остатки и операции: SQLite INTEGER с точностью 10^-9 Б (один нанобазарик = 10^-11 ₽), целые атомарные единицы. Округление в сторону увеличения один раз на окончательное оплачиваемое задание, до атомарной доли. Нулевой фактический расход списывает 0. Полную исходную сумму для сверки сохранять отдельно.
- В интерфейсе показывать разумное количество десятичных знаков и никогда не называть положительный расход нулевым: для очень малой суммы отображать «меньше 0,000001 Б». Оператор видит исходные точные суммы и источник.
- Базарики — внутренняя расчётная единица, не валюта для вывода и не передаваемые между людьми средства. Приём оплат/Telegram Stars — отдельная задача.

## 3. Расчётный месяц и бухгалтерия

- Первый якорь пользователя — первое явное обращение к боту: /start, команда, заявка или ручной вызов в группе, независимо от последующего разрешения. Пассивное появление в групповом авто-voice не устанавливает личный якорь.
- Якорь группы — первый переход в постоянно разрешённое состояние; по умолчанию ежемесячно 10 000 Б для авто, значение меняется администратором. Однократный доступ не открывает авто.
- Периоды меняются в 00:00 Europe/Moscow в календарное число якоря. Для 29/30/31 в более коротком месяце — последний день месяца; на следующий месяц возвращается исходное число. Все времена хранить с часовым поясом, не полагаться на локальные настройки VPS.
- При переходе периода неиспользованная бесплатная часть обнуляется и начисляется новый месячный лимит; разовые дополнительные начисления не сгорают. Бесплатные списываются прежде дополнительных.
- Администратор может назначить новое постоянное ежемесячное начисление либо разовое начисление на текущий период, а также дополнительный несгораемый остаток. Разницу между «изменить ежемесячную квоту» и «пополнить баланс» явно показывать.
- Атомарные записи с уникальными id операции и (subject, period) для месячного начисления, резерв/подтверждение/освобождение/корректировка в журнале. Никаких отрицательных доступных остатков, двойного начисления после рестарта или двойного подтверждения устаревшей кнопки.
- Все персональные и групповые остатки существуют независимо от состояния разрешения; отзыв доступа останавливает использование, но сам по себе не уничтожает оплаченные добавки. Корректировки доступны только администратору с подтверждением и аудитом.
- Исторические якоря при миграции брать из сохранённых достоверных данных: private_users.created_at, история индивидуальных обращений, groups.approved_at и т.п. Если первый контакт доказать нельзя, отдельно зафиксировать новый якорь без выдуманной даты. Не списывать задним числом расходы старых версий.

## 4. Личный и групповой бюджеты

| Вход | Проверяемое разрешение | Списываемый бюджет |
|---|---|---|
| Личное голосовое | admin или одобренный человек | личный |
| /tr reply в группе | разрешённая группа + достоверный вызывающий | личный |
| /trf reply/подпись | разрешённый контекст + отдельное право расширенного аудио + достоверный вызывающий | личный |
| Автоматическое новое voice в группе | постоянно разрешённая группа + auto_enabled | групповой |
| Кеш для ручного запроса | существующее разрешение | ноль |
| Нет достоверного user_id при ручном запросе | отказ | ничего |

- Автоматический обработчик сначала проверяет бюджет группы. Когда он исчерпан или тариф небезопасен, новые voice пропускаются **молча**, не изменяя auto_enabled. При новом месячном начислении возобновление происходит автоматически; пользователям не нужно повторять /auto_on.
- Во избежание ненужных автоматических ответов при исчерпанной групповой квоте даже результат из кеша не отправляется автоматически. Для явно выполненной ручной команды кеш доступен при действующем разрешении и без списания.
- Команда /status в группе выводит «Авто включено, приостановлено из-за бюджета», сколько осталось и дату начисления. /auto_on при истощённом бюджете подтверждает включение с предупреждением о приостановке.
- Нулевой групповой бюджет никогда не препятствует /tr, выполняемому за личные базарики. Личный бюджет никогда не используется без явного действия человека. Запрет группы не обходится личными средствами или статусом администратора бота.
- Сохраняются действующие суточные лимиты минут, ограничения частоты запросов, max_inflight, ограничение длительности/размера, одноразовые разрешения. Дополнительно вводится общий верхний месячный денежный предел на весь бот, настраиваемый владельцем. Начисленные квоты нескольких групп не обещают, что общий ресурс безграничен.
- Пользовательский баланс требуется также действующему администратору, но администратор может увеличить себе квоту. Анонимное ручное обращение без достоверного user_id не получает чужой баланс.
- При отказе на ручную команду сообщать причину (доступ, остаток, квота, тариф, предел бота); автоматический режим никаких уведомлений в чат не создаёт.

## 5. Обновление цен, модель поставщика

Фактический провайдер проекта — RouterAI по https://routerai.ru/api/v1, **не OpenRouter**. Последний использует другую валюту/каталог; адаптер для него можно добавить позже только отдельно, не конвертируя тарифы молча.

В agent-toolchain уже есть scripts/update_routerai_catalog.py, workflow routerai_catalog.yml, policy/snapshot/status. Повторно использовать схему проверки источника и разграничение владения данными. Важно: его текущая нормализация сохраняет pricing, но **отбрасывает pricing_units**, поэтому текущий опубликованный снимок нельзя использовать напрямую для безопасной финансовой тарификации STT. Нужен адаптер, сохраняющий единицы, и проверка актуальности независимо от задержек публикации PR.

Предлагаемое устройство:
1. Периодически (начальный интервал 6 ч) получать RouterAI GET /api/v1/models; при необходимости уточнять GET /api/v1/models/{author}/{model}/endpoints.
2. Принимать только проверенные записи с точными Decimal-ценами, единицами тарификации (second, token, request), валютой RUB, фактическим model ID, поддерживаемым методом STT, временем проверки и контрольной суммой. Политика разрешённых моделей и прав задаётся конфигурацией бота и **не** изменяется вместе с каталогом.
3. Атомарно публиковать новый проверенный снимок в отдельном runtime-хранилище. Не переустанавливать код, не запускать второго опросчика Telegram. Хранить последний успешный снимок и дату последнего обращения, не подменять один другим.
4. При невозможности обновления сохранять last-known-good; через конфигурируемый максимум давности (начальный ориентир 48 ч) запрещать новые платные задания по моделям с устаревшей/отсутствующей ценой. Крупные расхождения цены фиксировать и сообщать владельцу; рискованные модели блокировать до решения.
5. Бот показывает человеку дату и единицу тарифа; стоимость за минуту у duration-based и характер тарификации у token-based. Не выводить цену за минуту, если модель продаётся по токенам.
6. Выделить самостоятельный, непривилегированный ценовой обновлятор с ограниченным доступом на запись в отдельный локальный снимок. Планируемый таймер/расписание на VPS создавать только при отдельном разрешении на deployment.

Опасности: маршрутизация между провайдерами, смена цены после проверки, отдельная тарификация входных/выходных токенов и оформления, тарифные пороги. Перед списанием нужен доказуемый верхний предел расхода на выбранном маршруте. Для моделей без такого предела платные вызовы не допускаются автоматически. Тарифный каталог сам по себе не обеспечивает жёсткий потолок реальных списаний, если поставщик меняет цену/маршрут между проверкой и выполнением.

## 6. Фактическое списание и сверка

Документация RouterAI для /api/v1/audio/transcriptions описывает usage.cost (рубли), usage.seconds и заголовок X-Generation-Id. GET /api/v1/generation?id=<id> возвращает total_cost в рублях.

- Перед запросом: проверить актуальность цены, права, наличие персонального/группового/общего остатка и существующие пределы; в одной SQLite транзакции резервировать консервативный максимум и зарезервировать уникальность файла+модели+фактической модели провайдера.
- После успешного ответа: сохранить cost и Generation ID, при необходимости уточнить total_cost; отдельно учесть стоимость необязательного formatter. Проверенную сумму перевести в дробные базарики и финализировать один раз. Оставшуюся часть резерва освободить.
- Если цена из usage и /generation отличается, запись пометить несогласованной и выяснить, какое поле является финальным; без проверки не считать расхождение нулём. Оператор видит обе суммы. Для окончательной бухгалтерии приоритет — подтверждённый завершённый платёж поставщика.
- Если запрос точно не отправлен и не мог быть оплачен — освободить резерв. После попытки отправки с неизвестным исходом оставить блокировку/резерв и не повторять платный запрос автоматически. По сохранённому Generation ID выполнять только ограниченную повторную проверку метаданных.
- Если подтверждённая стоимость превышает резерв — не уходить в отрицательный пользовательский баланс; записать операторское превышение, приостановить небезопасную модель/маршрут, уведомить администратора. Без подтверждённой верхней границы нельзя обещать абсолютный денежный потолок.
- Для дополнительного оформления до вызова необходимо отдельное обеспечение ожидаемого расхода, либо отдать исходную расшифровку без платного оформления. Не выполнять незарезервированный formatter.
- Кеш (при действующих правах) не инициирует оплачиваемого вызова и не списывает базарики. При смене alias на другую реальную модель исключить использование результата из кеша от предыдущей модели.

Оставить нынешнюю защиту paid_store от дублирующихся и прерванных вызовов, переработав состояние для точного денежного журнала без автоматических retries.

## 7. Расширенное ручное распознавание

- /tr и автоматический обработчик остаются для Telegram voice (как сейчас).
- Новая /trf [alias] — ответ на voice, audio или document с аудиосодержимым; необязательная подпись /trf при отправке файла в личке, если поддерживается обработчиком команд подписи.
- /trf ? — выбор модели кнопками, привязанными к user_id, chat_id, message_id, сроку годности, проверке прав и бюджета при подтверждении. Нажатие чужой или старой кнопки не допускает списания.
- /trf разрешён только пользователю с отдельным расширенным правом (у админа — в рамках явной политики); одного разрешения группы недостаточно. В обычном авто-режиме audio/document никогда не передавать RouterAI.
- Проверять реальный формат, длительность, содержимое и допустимость, не доверять одному имени файла/MIME. Ограничить декодирование/FFmpeg по ресурсам, таймауту и ожидаемому размеру выхода; сохранять нынешний предел загрузки Telegram, лимит аудио и ограничение тела RouterAI JSON/base64. Длинные записи и видео отдельно.
- Пользователь перед подтверждением видит модель и сумму предварительного резерва; недорогие ручные команды могут выполняться без дополнительного подтверждения по настраиваемому порогу. При отсутствии безопасной оценки — отказ до платного вызова.

## 8. Пользовательский и административный интерфейсы

- /help: кратко что делает бот, /tr, /trf, /model, /balance, /status, ограничения и ссылка/команда /helphelp; коротко указать, что авто в группе оплачивается из группового, ручное — из личного.
- /helphelp: подробные разделы с кнопками — «Базарики», «Даты начисления», «Личный и групповой бюджет», «Стоимость и модели», «Файлы и команда /trf», «Кеш и спорные списания», «Как запросить пополнение», «Права и конфиденциальность». Показывать примеры дробных списаний и поведение при исчерпании бюджета.
- /balance: только личный чат; текущий доступный, бесплатный, дополнительный и зарезервированный остатки, дата следующего начисления, история, запрос пополнения. В группах не выдавать приватную финансовую историю.
- /model: список разрешённых моделей с тарифом, единицей, датой обновления и сообщением о недоступной цене. Выбор модели не повышает права и не отменяет лимиты.
- /status: личный короткий баланс; для группы — её отдельный бюджет, auto_enabled и состояние бюджетной приостановки.
- /access → Люди: разрешение для /trf, месячный лимит, изменение на текущий период/постоянно, разовое дополнительное начисление, история, подтверждение и аудит. /access → Группы: то же для месячного бюджета авто.
- /stats: администратору в личке — сводка базариков, реальных RUB RouterAI, расхождений и ожидающих сверки; без содержания файлов и расшифровок.
- Изменение настроек и начислений выполняется только по устойчивому Telegram user_id, не по username, и с защитой от повторных нажатий.

## 10. Подготовка и обновление на vserv

Фактическое состояние по последней задокументированной проверке: vserv, версия 0.2.0, один systemd-процесс, внешний config/env/SQLite и рабочая схема releases/current. Это historical evidence по docs/current_status_ru.md, перед новой установкой оператор заново читает runtime без изменения.

**Отдельно:** тарифы обновляются без перезапуска; обновление Python-кода остаётся управляемым, без автоматического применения GitHub main.

Процесс выпуска:
1. GitHub: все функциональные PR проверены, применены к main, известен точный SHA; CI без настоящих Telegram/RouterAI запросов. Проверить модификации миграции и безвозвратные изменения.
2. До сервера: проверить тестовую SQLite и три сценария: схема old → new, restart new → new, пробный откат new → old. Особое внимание: старый код не знает бюджетов базариков и при простом откате может снова выполнять неучтённые платные вызовы.
3. vserv read-only: подтвердить реального пользователя службы, SHA, текущий путь, активную конфигурацию, место и права на копии, текущую группу/лимиты. Определить точную целевую версию/схему и ожидаемое состояние. Не выводить секреты.
4. Через существующий scripts/update_bot.py выполнить check и prepare по точному SHA. Prepare — отдельное окружение, полные проверки и пробная миграция **копии** рабочей БД, не прекращая старый опросчик.
5. После отдельного разрешения на переключение выполнить apply, создать согласованную окончательную SQLite backup с учётом WAL, сохранить внешние секреты/настройки, переключить current и запустить ровно один опросчик.

- Пользователь: 1000 Б, пополнение, дрейф месяца 31 → февраль → 31, несколько перезапусков без второго начисления, частичные базарики, обычная команда за личный бюджет.
