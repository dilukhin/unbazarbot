# Миграция рабочего config.yaml

Инструкция для оператора существующего развёртывания, где `config.yaml` ранее отслеживался Git.
Изменения на VPS выполняются только по отдельному поручению пользователя.
Обычный `git pull` до сохранения файла может удалить рабочий конфиг.
Не копируйте пример поверх рабочего файла.

## 1. Проверить исходное состояние

В каталоге развёртывания проверьте `git status --short` и `git branch --show-current`.
При посторонних локальных правках или неожиданной ветке остановите обновление.
Определите фактический путь конфигурации: переменная окружения процесса/службы
`CONFIG_PATH`, затем `.env`, при отсутствии — `config.yaml`.
Не выводите содержимое `.env` в отчёт.
Команды ниже рассчитаны на стандартный путь `config.yaml`.

Если используется другой путь, сначала отдельно сохраните именно активный файл.
Если в рабочей копии также существует отслеживаемый `config.yaml`, сохраните и его.
Не меняйте `CONFIG_PATH` или настройки службы в рамках этого обновления.

## 2. Создать и проверить резервную копию до обновления

В одной сессии Bash из каталога проекта:

```bash
umask 077
config_backup_dir="$(mktemp -d "${HOME}/unbazarbot-config-backup.XXXXXX")"
cp -- config.yaml "$config_backup_dir/config.yaml"
cmp -- config.yaml "$config_backup_dir/config.yaml"
chmod 600 "$config_backup_dir/config.yaml"
```

Продолжайте только если все команды успешны. Запишите путь `config_backup_dir`
в закрытые эксплуатационные заметки. При разрыве сессии задайте переменную вновь
по сохранённому пути; не создавайте новую копию из уже обновлённого каталога.

## 3. Обновить код

Если `config.yaml` локально изменён, Git может отказаться обновлять его.
Только после успешного сравнения резервной копии можно вернуть этот единственный
файл к старому состоянию Git перед обновлением:

```bash
git restore --source=HEAD --worktree -- config.yaml
git pull --ff-only
```

Не используйте `reset --hard`, `clean` или принудительное обновление.
Если любая команда завершилась ошибкой, прекратите обновление и восстановите
`config.yaml` из проверенной резервной копии. Не перезапускайте бота в промежутке.
Другие изменения разрешайте отдельно.

## 4. Восстановить рабочий файл и проверить

После успешного обновления:

```bash
cp -- "$config_backup_dir/config.yaml" config.yaml
chmod 600 config.yaml
cmp -- "$config_backup_dir/config.yaml" config.yaml
git ls-files -- config.yaml
git check-ignore -- config.yaml
```

Ожидается: `cmp` успешен, `git ls-files` не выводит файл,
`git check-ignore` выводит `config.yaml`.
В активированном окружении бота проверьте загрузку без Telegram/RouterAI:

```bash
python -c "from voicebot.config import load_config; load_config('config.yaml'); print('Config OK')"
```

Для альтернативного `CONFIG_PATH` проверяйте активный путь.
Не удаляйте резервную копию до подтверждения нормальной работы.
Перезапуск, проверка Telegram и фиксация результата на VPS — отдельные
эксплуатационные действия. Этот документ не подтверждает их выполнение.

## Новая установка и откат

Для новой установки скопируйте `config.example.yaml` в `config.yaml`,
заполните имя бота и свой Telegram user ID. Пустой список администраторов
в шаблоне преднамеренный. Не помещайте токены в YAML.

При откате к версии, где `config.yaml` снова отслеживается, сначала сохраните
активный конфиг вне репозитория. Git может отказаться переключать версию из-за
локального неотслеживаемого файла; не обходите отказ принудительными командами.
После согласованного отката восстановите сохранённые настройки и проверьте их
загрузку до перезапуска.

Удалённый из текущего дерева ID остаётся в старых коммитах. Переписывание
истории не входит в эту миграцию.
