# Ручные аудиофайлы и проверка содержимого (#22)

## Команды и права

Обычная `/tr` и групповой авто-режим принимают только Telegram voice.
Расширенная `/trf [alias]` применяется в ответ на voice, audio или документ
с аудио. В личке можно отправить файл с подписью `/trf [alias]`.
Отправка обычного audio/document без команды не запускает распознавание.
Видео, PDF и произвольные документы не поддерживаются.

У `/trf` отдельное личное разрешение `private_users.trf_allowed`, по умолчанию 0,
включая администратора бота. Группового разрешения недостаточно. Обычный доступ
к контексту проверяется отдельно; ручной вызов расходует личные базарики.
Изменение отдельного разрешения проверяет действующего администратора внутри
транзакции, увеличивает revision и записывается в аудит. Отзыв/отклонение личного
доступа снимает расширенное право. Интерфейс управления правом — следующий #23;
оператору не требуется редактировать SQLite вручную.

`/trf ?` показывает статус и предварительный резерв моделей. Для файла доступны
кнопки безопасно оценённых моделей. Кнопка привязана к владельцу, чату, сообщению
меню, целевому аудио, alias, сроку 5 минут и поколению отдельного разрешения.
Однократное использование фиксируется в SQLite. Чужая, старая, подменённая или
повторная кнопка не допускает оплату. Отзыв и повторная выдача права не оживляют
старые кнопки. После выбора снова проверяются контекст, бюджет, актуальный тариф
и право непосредственно перед HTTP POST; цена меню не разрешает обход проверки.

## Безопасная подготовка каждого нового платного аудио

Проверка содержимого применяется также к обычному voice: метаданные Telegram
сами по себе не доказывают верхнюю длительность оплачиваемого файла.
Денежный резерв, права, дубль и первичные пределы проверяются **до скачивания**.
В процессе работает один слот скачивания/подготовки; второй запрос получает
отказ до новой подготовки. Дополнительно действует общий max_inflight.

1. Размер проверяется по метаданным и фактически полученным байтам; частичный
   файл удаляется при отказе. Верхняя граница — меньшее из настройки и 20 МиБ;
   облачный Telegram Bot API имеет собственный download cap 20 MB и также
   может отказать до загрузки. Обход через локальный Bot API не добавляется.
2. Тип определяется по содержимому: WAV, OGG, FLAC, MP3, AAC, MP4/M4A или WebM.
   Расширение и MIME не выдают допуск. Плейлисты и неизвестные сигнатуры запрещены.
3. ffprobe вызывается с принудительно выбранным демультиплексором. Требуется
   ровно один аудиопоток без видео/вложений, известная конечная длительность,
   до 8 каналов и частота до 192 кГц. В MP4 отключены внешние дорожки и абсолютные
   ссылки; разрешены только локальный file/pipe, сетевых протоколов нет.
4. FFmpeg полностью декодирует и нормализует аудио в один поток 16 кГц/моно,
   удаляет метаданные. Выход — OGG, MP3, WAV или FLAC согласно формату модели.
   После декодирования длительность проверяется заново. Ограничение выхода
   `max_audio_seconds+1` не разрешает отправить усечённый длинный файл: если
   декодированная длительность больше предела, запрос отклоняется.
5. Допуск 0,1 с относится только к контейнерному/кодековому заполнению. Денежная
   оценка использует `max_audio_seconds+1`; минутный резерв уточняется вверх по
   проверенной длительности и повторно проверяет все суточные минутные пределы.
6. Тело RouterAI сериализуется до окончательного допуска отправки. Полный JSON
   вместе с base64 ограничен 32 МиБ; ошибка подготовки считается доказанно
   неотправленным запросом и освобождает резерв по финансовому договору.

Официальные ограничения: [Telegram getFile](https://core.telegram.org/bots/api#getfile),
[RouterAI STT](https://routerai.ru/docs/guides/overview/multimodal/speech-to-text.md).

## Ресурсы, данные и отказ

Linux-компоненты: `ffmpeg`, `ffprobe`, `prlimit` (util-linux). Они не устанавливаются
ботом автоматически. Отсутствие инструмента или несовместимая сборка блокирует
новый платный вызов; бесплатный кеш продолжает работать при действующих правах.

Каждый дочерний процесс ограничен через prlimit: 512 МиБ адресного пространства,
20 секунд CPU, размер выходного файла по общему пределу, 64 дескриптора и 256
процессов/потоков для UID (этот предел учитывает также уже работающие процессы
пользователя; обработка FFmpeg остаётся однопоточной). Лимит адресного пространства включает отображённые библиотеки
и не равен фактически потребляемой памяти. Дополнительно 45 секунд по часам,
один поток кодека/фильтров, 64 МиБ одной аллокации, не более 1 МиБ stdout
и 64 КиБ stderr. При таймауте/отмене завершается собственная группа процессов,
каналы дочитываются, слот освобождается. Это подготовка аудио, не локальное ASR.

Дочерний процесс не получает окружение с Telegram/RouterAI ключами. Shell не
используется; имя пользователя не становится аргументом команды. Исходный файл
0600 и отдельный временный каталог 0700 удаляются после задания; нормализованный
файл имеет 0600. Сырые stderr, аудио и расшифровки не попадают в отчёты/логи.
В trf_choices временно хранятся только Telegram file IDs и метаданные выбора.

При любой проверке до отправки освобождаются деньги и одноразовое право с
проверкой поколения доступа. Неподтверждённый исход после отправки не повторяется.
Обычный групповой auto остаётся тихим при финансовом/тарифном отказе.

## Проверки и выпуск

Тесты создают искусственный WAV, проверяют реальное преобразование WAV/OGG/MP3/
FLAC, повреждённые данные и превышение длительности; отдельно имитируют таймаут,
очистку, поддельные метаданные и переполнение загрузки. HTTP платного провайдера
не вызывается. CI Python 3.10/3.12 устанавливает медиа-инструменты только в
одноразовый GitHub runner; production и системные пакеты vserv не изменяются.

Перед выпуском #24 оператор подтверждает наличие/версии инструментов, права и
совместимость с ресурсами vserv на искусственном файле. Автоматическая установка
пакетов или изменение systemd не входит в этот этап. Выдача новых прав /trf,
денежный лимит и production apply требуют существующего управляемого выпуска.
Тарифная зависимость agent-toolchain #113 по-прежнему блокирует рабочие STT.
