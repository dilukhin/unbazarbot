# Распознавание в Max: подготовленная интеграция

Статус: код без проверки на реальном боте. Основной вход Telegram (`bot.py`) не меняется. Отсутствие профиля и токена Max не позволяет подтвердить доставку нативных голосовых сообщений, групповую работу и запуск на VPS.

## Схема

Max отправляет HTTPS-уведомление на `/max/webhook`; сервер проверяет заголовок `X-Max-Bot-Api-Secret`, сохраняет событие в отдельную SQLite-базу и быстро отвечает. Один рабочий цикл обрабатывает очередь: проверяет разрешение, формат, размер и длительность, скачивает аудио во временный файл, вызывает существующий `RouterAITranscriber`, сохраняет результат и отвечает в Max. После аварийного прерывания задача со статусом `interrupted` не повторяется автоматически: внешний вызов мог быть оплачен.

У Telegram и Max разные конфигурации, базы и идентификаторы пользователей. Администратор Max указывается числовым `user_id` Max. Личная расшифровка доступна только указанным администраторам. Группы закрыты, пока администратор не выполнит `/approve_once <chat_id>` или `/approve_forever <chat_id>` в личном диалоге. `/reject` и `/revoke` отменяют разрешение. `/auto_on` действует только после постоянного разрешения. Команда `/tr [модель]` применяется как ответ на аудио; `/model` выводит модели, `/model set <имя>` выбирает модель разрешённого чата. Расшифровка повторного сообщения той же моделью берётся из отдельной базы Max.

Текущий код запрещает MP3. Файлы других форматов и входящий тип `audio` принимаются только при распознанном формате; список разрешённых адресов загрузки задаётся точными именами узлов в конфигурации. Если Max изменит домен вложений, его нужно проверить на реальном событии и добавить в локальную конфигурацию. Исходное аудио удаляется после обработки. Нет общего бюджета между двумя мессенджерами; перед открытием широкой аудитории нужно выполнить issue #6.

## Подготовка (после получения доступа Max)

1. Создать подтверждённый профиль организации, ИП или самозанятого на платформе Max и зарегистрировать бота. Не передавать токен в GitHub или переписку.
2. Скопировать `max_config.example.yaml` в исключённый из Git `max_config.yaml`, указать свой Max `user_id` администратора и проверить узлы адресов аудиовложений. Telegram `config.yaml` не использовать для Max.
3. В защищённом окружении задать `MAX_BOT_TOKEN`, `MAX_WEBHOOK_SECRET`, `ROUTERAI_API_KEY`, при необходимости `MAX_CONFIG_PATH` и `MAX_DB_PATH`. Для Max по умолчанию используется `data/maxbot.sqlite3`; не направлять его на Telegram-базу. Секрет подписки — не менее пяти символов; рекомендуем случайное длинное значение.
4. Установить зависимости и запустить `uvicorn maxbot.app:create_app --factory --host 127.0.0.1 --port 8080` за обратным прокси с HTTPS на порту 443 и доверенным сертификатом. Разрешить вход на `/max/webhook` только через прокси. Реальную подписку `POST /subscriptions` с адресом `https://<домен>/max/webhook`, событиями `message_created`, `bot_added` и тем же `secret` создать отдельно после проверки домена. Код сам подписку не создаёт.
5. Администратор сначала начинает личный диалог с ботом, чтобы бот мог присылать уведомления. Проверить отдельно аудиофайл, нативное голосовое, ответ `/tr` на старое сообщение, группу, одноразовое разрешение, отзыв, повторное уведомление и прерывание во время вызова RouterAI.

## Известные ограничения

- Открытая заявка Max описывает нативное голосовое, которое приходит без `message` и не видно в `/messages`. При таком событии код регистрирует отсутствие тела без попытки платного распознавания. Поддержка голосовых требует реальной проверки после создания бота: https://github.com/max-messenger/max-bot-api-client-ts/issues/250
- Структуру `link.message` для ответа на старое аудио и адреса вложений нужно подтвердить на реальном событии. При отсутствии вложенного сообщения `/tr` отвечает инструкцией, не расходуя баланс.
- Текущий один рабочий цикл обрабатывает события последовательно. Ошибочные события сохраняются со статусом `error`; операция восстановления после неопределённого исхода платного вызова требует отдельного решения.
- Подтверждение создания бота, работа HTTPS и настройка VPS не выполнялись. Работающий в Telegram бот не затронут.
