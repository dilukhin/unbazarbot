# Проверенные тарифы и предварительная оценка (#18)

## Источник и доверие

Бот получает только проверенный документ общего поставщика agent-toolchain #110.
Контракт включён в main поставщика через [PR #111](https://github.com/dilukhin/agent-toolchain/pull/111)
и [исправление #112](https://github.com/dilukhin/agent-toolchain/pull/112).
Первый опубликованный документ принят клиентом 28.10.2026: 579 моделей,
`source_checked_at=2026-10-28T20:43:18Z`, проверка validate run 40765886627
точного кандидата `aa59d1ba96fe990b84e30473cb836acff1124b92`.
Его hash — `sha256:c6913cc2590568e291eee0899d693861c4e57dd7839355761fb4fced8b383128`.
Проверены схема, локальное сохранение и повторное чтение того же hash.
HTTP smoke получил JSON через urllib; HTTP-обработчик клиента проверен на этих
же байтах через тестовый transport, поскольку окружение требует SOCKS-зависимость.
Такая ошибка настройки клиента теперь оставляет кеш и не завершает фоновый цикл.
Установка на vserv не выполнялась.

Фиксированный URL:

`https://raw.githubusercontent.com/dilukhin/agent-toolchain/refs/heads/automation/routerai-prices/routerai-prices.json`

Кандидат `automation/routerai-catalog`, PR #34, старый generated snapshot `main`
и heartbeat другого набора не используются. Запросов к RouterAI `/models` у
бота нет. Сопоставление alias → provider_model остаётся только в рабочем config;
новые модели каталога не добавляют моделей бота или разрешений.

`voicebot/tariffs.py` проверяет schema 1, owner, publisher, notice, `published`,
точный источник, RUB, SHA-256 канонического content, доказательство Windows/Linux
проверки с SHA/run_id, UTC-даты, модель, API, модальности, каждый маршрут, units
и ручные денежные пределы. Hash — контроль целостности, не цифровая подпись;
доверие основано на фиксированном HTTPS-канале доверенного репозитория.
Полный пример без реальных запросов: `tests/fixtures/routerai_prices_published.json`,
тот же эталонный JSON, что в тестах поставщика.

Неполные, переменные, неподтверждённые и несовместимые записи не дают денежного
допуска. Одна явно непригодная модель не выключает другую проверенную модель.
Публичные Whisper endpoints на момент разработки не подтверждают API, а
положительный токенный компонент нельзя считать секундной ценой. Такие данные
не обходятся догадкой. До устранения этой неопределённости платный вызов может
оставаться заблокированным даже после появления канала.

## Получение и сохранение

Параметры `tariffs` (без секретов и произвольного URL):

| Параметр | По умолчанию |
|---|---|
| `refresh_seconds` | 21 600 (6 часов) |
| `max_age_seconds` | 172 800 (48 часов) |
| `timeout_seconds` | 15 |

Один фоновый процесс внутри существующего bot-poller выполняет проверку; нового
poller, cron или systemd timer нет. Один HTTP GET на попытку, без автоматических
повторов, с ETag, без перенаправлений и без Authorization. Предел распакованного
ответа — 8 МиБ. `304` не меняет `source_checked_at` и не продлевает свежесть.
Проверка и сохранение выполняются в рабочем потоке, не блокируя long polling.

`TARIFF_CACHE_PATH` — абсолютный путь к внешнему файлу, например
`/var/lib/unbazarbot/routerai-prices.json`. По умолчанию файл располагается рядом
с **внешней** `DB_PATH`. Старт запрещает размещение внутри дерева кода/выпуска;
при разработке также укажите отдельный runtime-каталог. Не добавлять этот файл
в Git, каталог выпуска, Project Sources или репозиторную фикстуру.

Кеш создаётся через временный файл 0600, fsync и атомарный replace. Блокировка
файла сериализует независимые обновляторы; повторная проверка сохранённой версии
не даёт старому ответу затереть новый. Повреждённый локальный файл восстанавливается
только из полностью проверенного удалённого документа. Неверный новый документ,
ошибка сети, диска или таймаут сохраняют предыдущие данные. При рестарте кеш снова
проверяется; дата его чтения не превращается в дату проверки RouterAI.

Свежесть определяется только `source_checked_at` **этого hash**. Истёкшие,
будущие, более старые и повторно использованные для другого hash наблюдения
не разрешают оплату. Старый локальный снимок хранится для диагностики, но после
истечения срока новый вызов блокируется.

## Интерфейс расчёта для #19/#20

`PriceCatalog.estimate(model_id, quantities, api=...)` возвращает неизменяемый
`Estimate`: status/reason, `max_rub`, `bazariki`, `observed_rub`, `snapshot_id`,
`checked_at`. Количества — `Quantity(Decimal(...), unit)` для каждого положительного
компонента. Отсутствующее количество не считается нулём. Несовпадение token,
second и request запрещает оценку. Числа float не принимаются.

Предварительная верхняя оценка использует все положительные `price_ceilings`,
включая возможные компоненты резервных маршрутов. `observed_rub` — максимальная
каталожная оценка по всем текущим провайдерам; **ни одно из этих полей не является
фактическим списанием RouterAI**. Перевод: `bazariki = max_rub × 100` (1 Б = 0,01 ₽),
без округления в тарифном слое. Пример: `0.000123 ₽/second × 60 second = 0.007380 ₽
= 0.738000 Б`. Точность Decimal при вычислении — 400 знаков, вход цены и количества до 80 символов,
верхнее количество не более 10^12. #19/#20 выполнят единственное округление вверх
к атомарной доле и сохранят исходную точную стоимость отдельно.

`estimate_audio` может доказать секунды и единичный запрос; положительные токены
без доказанной верхней границы дают `unsafe`. Для обычного voice используется
консервативный предел `limits.max_audio_seconds + 1`, а не рекламная минимальная
ставка провайдера. Предел длительности Telegram остаётся прежним; проверка
реального содержимого расширенных файлов относится к #22.

Состояния: `available`, `unavailable`, `unpriced`, `stale`, `incompatible`, `unsafe`.
В Estimate нет баланса пользователя: это вход будущей атомарной резервации, не
замена проверке прав, месячных бюджетов или общей денежной квоты.

## Оплата и пользовательские команды

Новая платная обработка проверяет тариф до скачивания, после скачивания и
непосредственно перед STT. Кеш при действующем доступе возвращается до тарифной
проверки и не вызывает RouterAI. Отказы auto не меняют `auto_enabled` и не
сообщают о тарифе в группу; ручной вызов сообщает причину. Прежняя атомарная
защита от дубликатов, лимиты и разрешения сохраняются. При истечении тарифа до отправки финансовый слой освобождает доказанно
неотправленный резерв, не обходя нового отзыва доступа. После возможной
отправки неизвестный исход сохраняет резерв. [Резерв и сверка](financial_costs_ru.md).
Сам тарифный слой денежных списаний не выполняет.

`/model` показывает статус, единицы, дату проверки и консервативную оценку для
разрешённых конфигурацией моделей; токенная модель не получает выдуманную ставку
за минуту. `/stats` остаётся только администратору в личке и показывает hash,
дату и причину деградации без расшифровок или личной бухгалтерии.

**Дополнительное платное оформление временно не выполняется**, даже если старый
config содержит `formatter.enabled: true`: #20 должен обеспечить отдельный
денежный резерв. Исходный STT сохраняется; прежний оформленный кеш остаётся
бесплатным. Прямые компонентные тесты formatter сохранены, но бот не вызывает
его без финансовой защиты. Этот факт нужно учитывать при приёмке обновления.

Для аварийной остановки новых платных вызовов оператор может создать пустой
`<TARIFF_CACHE_PATH>.paused` во внешнем runtime-каталоге. Маркер проверяется перед
каждым вызовом без перезапуска; его удаление возвращает обычные проверки тарифов.
Слой не обещает абсолютного потолка при неограниченном изменении RouterAI цены
после проверки: окончательная защита и остановка по перерасходу — #20.

## Границы и выпуск

Исторические REAL-записи сохраняются. Новый денежный журнал использует INTEGER,
а точные RUB и Generation ID сохраняет финансовый слой #19–21;
[правила списания и маршрутизации](financial_costs_ru.md). `/trf`, `/balance`,
`/helphelp` и расширенные права — #22–23. Здесь новые платные пути не открываются.

Перед производственным обновлением (#24):

1. Слить и проверить поставщика, прочитать именно опубликованный артефакт и его
   hash/единицы/свежесть. Подтвердить пригодность выбранных рабочих моделей.
2. Проверить этот код в main и CI Python 3.10/3.12; пройти финансовые зависимости
   #19/#20 до включения новых платных возможностей.
3. Отдельным поручением выполнить существующий `check → prepare → apply`, сохранить
   внешние config/env/SQLite и тарифный кеш с lock/pause-маркером. Рабочий YAML
   не заменять шаблоном; старый config без `tariffs` получает безопасные значения.
4. После нового запуска SQLite не откатывать автоматически; старый код не знает
   тарифного запрета. Для остановки использовать маркер или остановку службы.

Проверки: `python -m pytest -q`; `python -m compileall -q bot.py voicebot scripts tests`.
Все тарифные и маршрутные тесты используют искусственные данные/HTTP transport.
Ни реальные платные запросы, ни производство этими проверками не затрагиваются.
