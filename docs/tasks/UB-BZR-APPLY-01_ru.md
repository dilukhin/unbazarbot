## Что покрывает отдельное разрешение на это задание

Повторные штатные check/prepare-проверки; закрытый маркер запрета новых оплат
`.paused`; резервные копии config/env/SQLite/тарифного кеша только на сервере;
stop/start только unbazarbot.service через имеющиеся права; атомарное переключение
current на TARGET_SHA; штатная миграция рабочей SQLite самой новой версией;
проверка здоровья и единственного процесса. Возможен краткий перерыв работы бота.

Новые платные распознавания после установки должны оставаться заблокированными;
доступны команды и бесплатный кеш при действующих правах. Рабочий YAML/env,
положительные бюджеты, персональные/групповые права и права /trf не менять.
Не выполнять платные POST, оформитель текста, BotFather, обновление ОС/FFmpeg/
Python, sudoers, systemd unit/daemon-reload или перезагрузку VPS. Не сливать PR
документации до завершения этого окна и не изменять GitHub из агента.

## Порядок

1. Прочитать фактическую справку/правила установленного ssh-relay. Подтвердить
   доверенный канал, пользователя, версию/current и один активный процесс по
   закрытым материалам прежнего сеанса. Пути исходников, releases, current,
   config, env, SQLite, backups взять из прежней серверной подготовки, не из
   публичных примеров. Не сканировать другие проекты. Если состояние отличается,
   канал/права отсутствуют или доверие изменилось, вернуть блокировку до записи.
2. Проверить чистоту исходной копии и точный origin dilukhin/unbazarbot. Python
   3.12.15 действующего выпуска и контроллер из TARGET_SHA; не системный Python
   3.8.10 и не старый контроллер. Штатный check должен вернуть ровно TARGET_SHA.
   Сверить REVISION/.ready подготовленного выпуска; не редактировать манифест и
   не пересоздавать выпуск принудительно. При изменении main остановиться,
   вернуть SHA Work; новый SHA самостоятельно не выбирать.
3. До любого stop проверяющим процессом разрешено прочитать необходимые
   значения config/env без вывода. По /proc/MainPID/environ внутри проверяющего
   процесса сопоставить только CONFIG_PATH, DB_PATH, TARIFF_CACHE_PATH и LOCK_PATH
   с EnvironmentFile и штатными значениями по умолчанию; не выводить окружение
   или читать его через команды, печатающие все переменные. При противоречии
   остановиться. Установить фактический тарифный путь по
   TARIFF_CACHE_PATH либо штатному пути рядом с SQLite. Проверить его и .paused
   через validate_tariff_path с реальными database/config/env/LOCK_PATH и корнями
   исходников/releases. Проверить закрытый родительский каталог и владельца.
   Если .paused отсутствует, создать ровно этот обычный файл 0600 без перезаписи
   и перехода по ссылке (O_CREAT|O_EXCL|O_NOFOLLOW). Если уже есть — проверить
   обычный файл/0600/владельца и сохранить его. Не трогать тарифный .lock.
   Конфигурацию/env и их денежные значения не менять. Маркер не удалять ни при
   успехе, ни после ошибки; возвращение к оплате — отдельное поручение.
4. Без запуска bot.py проверить запрет estimate_audio на фактическом тарифном
   пути: PriceCatalog должен вернуть unsafe / paid-requests-paused. Без сети и
   без записи каталога; одного наличия имени маркера недостаточно. Если путь
   не подтверждён или запрет не сработал, apply запрещён.
5. Выполнить штатный scripts/update_bot.py apply с теми же путями и TARGET_SHA,
   что в успешном prepare; --sudo только при имеющемся неинтерактивном праве
   управления этой службой. Не менять sudoers и не получать новые привилегии.
   Скрипт повторяет хеши/договор/медиа/trial, сверяет main, пути службы,
   единственный EnvironmentFile и KillMode=control-group; до stop сохраняет
   закрытые config/env, после stop делает согласованный окончательный SQLite
   backup с WAL/quick_check и копию тарифов/.paused, затем переключает current,
   запускает службу, наблюдает 10 секунд и проверяет рабочую SQLite.
   Никакой ручной подмены этапов, rsync поверх current или второго опросчика.
6. При успехе отдельно подтвердить: current и REVISION равны TARGET_SHA,

7. Не вызывать Telegram getUpdates, не входить в пользовательские аккаунты и

## Ошибка

До запуска нового процесса действует штатное восстановление прежнего выпуска.
После попытки запуска новой версии контроллер возвращает старую ссылку, но
**оставляет службу остановленной и сохраняет текущую БД**. Не выполнять ручной
start прежней 0.2.0, SQLite restore/замену/удаление WAL, очистку денежных таблиц
или маркера схемы. Сначала вернуть обезличенный этап/код ошибки Work. Ошибка
или несовпадение состояния не разрешают расширить это задание. Снимок prepare
не подставлять вместо окончательного backup и текущей базы.
