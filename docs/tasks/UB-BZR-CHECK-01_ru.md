[Приёмка и опубликованный снимок](../bzr_release_acceptance_ru.md).

Work выполнил GitHub, разработку, тесты, публикацию и настоящее HTTPS-чтение
каталога. Агенту остаётся только недоступное Work чтение серверного состояния
через уже доверенный ssh_relay vserv. Ничего разрабатывать, устанавливать,
обновлять, тестировать платным запросом или менять в GitHub не требуется.
Это задание **не разрешает prepare/apply или изменение рабочей среды**.

## Выполнение

Использовать доступный aragorn либо dima-hp и существующий доверенный канал.
Сначала прочитать установленный навык ssh-relay и справку фактического CLI;
синтаксис команд не угадывать. Если канал недоступен, права отсутствуют или
идентичность узла изменилась, вернуть ограничение; не создавать новые ключи,
учётные записи или доверие и не менять сетевые настройки ради обхода.

Одним ограниченным сеансом выполнить только чтения:

1. Подтвердить узел/ОС и UTC-время. Для unbazarbot.service получить выбранные
   свойства: ActiveState, SubState, MainPID, User, Group, WorkingDirectory,
   EnvironmentFiles, ControlGroup, KillMode, NRestarts. Не выводить Environment,
   полную командную строку процессов или содержимое unit-файла: там могут быть
   чувствительные значения. Через /proc/MainPID/exe и cwd подтвердить фактические
   интерпретатор и каталог. По cgroup.procs посчитать процессы именно этой службы,
   не собирать общий ps других проектов.
2. Установить текущую ревизию по существующему release marker/цели ссылки current.
   Из .ready при необходимости прочитать только revision, из исходного файла
   версии — только версию. Не импортировать bot.py/приложение и не запускать
   второй опросчик Telegram. Историю Git и сетевой GitHub здесь не получать:
   целевые SHA уже проверены Work.
3. Получить версии существующих Python, ffmpeg, ffprobe, prlimit (только version/help).
   Ничего не устанавливать, не выполнять преобразование рабочих аудиофайлов.
   Пробный media_doctor и миграция копии относятся к будущему разрешённому prepare.
4. Проверить доступное место/память; метаданные путей runtime/current/releases,
   config, файла окружения, SQLite и каталога существующих копий: наличие,
   владелец, права, размер, цель ссылки. Не читать содержимое .env, конфигурации,
   SQLite/WAL/SHM, аудио, кеша расшифровок или journald. Не создавать копий,
   каталогов, выпусков, lock/pause-файлов и не выполнять chmod/chown на сервере.
   Если путь нельзя уверенно определить из уже известных метаданных — отметить
   unknown, а не сканировать домашний каталог или файловую систему.
5. По метаданным существующих копий отметить дату последней подходящей копии,
   если она однозначно определяется. Не открывать архивы/SQLite и не заявлять
   проверку восстановления: её предстоит выполнить штатной процедурой.

Разрешены только приведённые диагностические чтения. Не выполнять systemctl
stop/start/restart/daemon-reload, check с побочными загрузками/записями неизвестной
версии скрипта, prepare/apply, pip/apt/git fetch/pull, миграции, SQLite checkpoint,
изменения config/env, прав, бюджетов, BotFather, RouterAI-аккаунта или платные POST.
Существующий ключ для этого задания не нужен и не читается.

## Возврат

Сохранить только на машине агента в отдельном закрытом каталоге задания:
UB-BZR-CHECK-01_report.json и короткий отчёт по-русски. Указать проверенный узел,
время, установленную ревизию/версию, состояние службы, KillMode, число процессов
в cgroup, версии инструментов, ресурсы/права/внешние пути и unknown/ограничения.
Тексты ключей, окружения, командных строк и пользовательские сведения исключить.
Рабочие пути остаются в частном отчёте; автоматически в GitHub ничего не публиковать.

После возврата Work сопоставит результат с договором выпуска и подготовит точные
действия. Применение на production, конечный общий суточный RUB-предел и окно
обновления потребуют отдельного поручения владельца. Результат этого задания
не является разрешением на запуск новой версии или открытие новых оплат.
