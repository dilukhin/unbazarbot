# Перенос Telegram-бота с v5 на vserv

Дата подготовки: 2026-10-06. Исполнитель: локальный агент с доступом к обоим серверам.
Репозиторий: `dilukhin/unbazarbot`. Цель: перенести действующий экземпляр
`@unbazarbot`, сохранив рабочую конфигурацию, базу и разрешения, обновить код,
затем установить аватар. Бот Max из чернового PR #9 в этот перенос не входит.

## Исходные данные и границы

- Источник по сообщению пользователя: v5, 95.81.118.143 (Serv-Tech).
- Назначение: vserv, 185.79.138.72 (Weasel).
- Сначала проверить подлинность узлов и фактическое размещение бота через
  доверенный канал доступа. Адреса сами по себе не подтверждают роль сервера.
- Использовать принятый в проекте канал удалённого исполнения и его правила
  разрешений. Не выводить токены, содержимое `.env`, ключ RouterAI, базу или
  расшифровки в отчёт и журналы. Не помещать их в Git.
- Переносить только Telegram-бота из `main` после слияния проверенного PR.
  В PR #7 конфигурация отделена от Git. На старом сервере
  `config.yaml` может ещё отслеживаться: сохранить его до любого обновления. Рабочую конфигурацию хранить отдельно от рабочей копии
  и задавать через `CONFIG_PATH`; не перезаписывать её обновлением Git.

## Подготовка без остановки источника

1. На v5 установить фактический каталог, способ запуска, активную ревизию,
   `CONFIG_PATH`, `DB_PATH`, расположение `.env`, права доступа и число
   процессов long polling. Не доверять путям из примера systemd.
2. Проверить свободное место и необходимые Python, ffmpeg, sqlite3 на vserv.
   Развернуть утверждённый `main` в новой рабочей копии и отдельном окружении.
   Установить зависимости и выполнить `python -m unittest discover -s tests -v`.
3. Скопировать конфигурацию и секреты защищённым каналом во внешние по
   отношению к Git пути на vserv с минимальными правами. Проверить синтаксис
   конфигурации и соответствие `getMe.username` значению `unbazarbot`,
   не записывая токен в командную строку или отчёт.
4. Сохранить на v5 отдельные копии рабочей конфигурации и базы; для SQLite
   использовать согласованную резервную копию (SQLite backup), учитывая WAL.
   Выполнить пробное восстановление на vserv без запуска второго опросчика.
5. Подготовить службу на vserv с `WorkingDirectory`, `EnvironmentFile`,
   `CONFIG_PATH`, `DB_PATH` и путём к виртуальному окружению, соответствующими
   фактическим путям. Службу пока не запускать.

## Переключение и проверка

1. В согласованное окно остановить старый процесс/службу на v5 и убедиться,
   что он действительно остановился. Бот использует long polling: одновременно
   два экземпляра с одним токеном запускать нельзя.
2. После остановки создать окончательную согласованную резервную копию SQLite
   и перенести её на vserv. Сверить целостность, число групп, заявок, разрешений
   и ключевых записей без публикации идентификаторов и содержимого.
3. Запустить один экземпляр на vserv. Проверить `systemctl status`/журнал без
   раскрытия секретов и отсутствие второго опросчика на v5. В личке проверить
   `/start` и `/status`, затем в разрешённой группе `/tr` на голосовое,
   отказ на обычное `audio` и тихий пропуск музыки при `/auto_on`. Для
   внешнего вызова RouterAI использовать короткое безличное тестовое голосовое.
   Убедиться, что отказ и пропуск не создали оплачиваемого вызова.
4. Установить аватар из
   `assets/bazarbot-telegram-avatar-500.jpg` для этого же бота.
   Исходник — `bazarbot-max-logo-500.png` пользователя из Библиотеки;
   JPEG нужен для метода Telegram Bot API `setMyProfilePhoto`.
   Перед изменением проверить `getMe.username == "unbazarbot"`.
   Передать файл как новую multipart-загрузку и проверить успешный ответ и
   отображение изображения в Telegram. Токен не печатать и не сохранять в коде.
5. Подтвердить, что служба переживает завершение сеанса и имеет заданный
   порядок автозапуска. Сохранить прежние данные и службу v5 для отката,
   оставив старую службу выключенной.

## Откат и отчёт

При сбое остановить экземпляр на vserv **до** запуска v5. Если vserv успел
принять сообщения, не заменять его базу старой без оценки новых записей.
Сообщить, какой экземпляр работает, какая ревизия установлена, результаты
проверок и состояние аватара. Для успешного переноса указать хеш ревизии,
способ запуска, результат проверки единственного опросчика, целостности
SQLite и голосового/музыкального сценария. Секреты и личные данные не включать.

Примечание: текущий `bot.py` при запуске удаляет webhook с
`drop_pending_updates=True`; сообщения, накопленные во время переключения,
могут быть пропущены. Свести окно остановки к минимуму и отразить его в отчёте.
